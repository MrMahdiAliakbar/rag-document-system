<a id="api-fa-overview"></a>
## 🌐 معرفی

این API با استفاده از Django REST Framework پیاده‌سازی شده و امکانات مدیریت اسناد، دریافت پاسخ به پرسش‌ها و مشاهده تاریخچه پرسش‌ها را فراهم می‌کند.

**آدرس پایه:**

```text
http://localhost:8000/api/
```

**انواع محتوای پشتیبانی‌شده:**

- `application/json` برای درخواست‌های JSON
- `multipart/form-data` برای بارگذاری اسناد و جایگزینی فایل‌ها

<a id="api-fa-endpoints"></a>
## 📡 نقاط پایانی API

### مدیریت اسناد

اسناد با فرمت DOCX بارگذاری می‌شوند، سپس پردازش شده، به بخش‌های کوچک‌تر تقسیم می‌شوند و برای بازیابی اطلاعات ذخیره می‌شوند.

| متد | نقطه پایانی | توضیحات |
|---|---|---|
| GET | `/api/documents/` | دریافت فهرست تمام اسناد |
| POST | `/api/documents/` | بارگذاری سند جدید |
| GET | `/api/documents/{id}/` | دریافت اطلاعات یک سند مشخص |
| PUT | `/api/documents/{id}/` | به‌روزرسانی کامل سند |
| PATCH | `/api/documents/{id}/` | به‌روزرسانی جزئی سند |
| DELETE | `/api/documents/{id}/` | حذف سند |

**بارگذاری سند**

`POST /api/documents/`

نوع محتوای درخواست: `multipart/form-data`

| فیلد | نوع | الزامی | توضیحات |
|---|---|---|---|
| `title` | String | بله | عنوان سند |
| `file` | File | بله | فایل DOCX |

**به‌روزرسانی سند**

`PUT /api/documents/{id}/`

درخواست PUT برای به‌روزرسانی کامل سند استفاده می‌شود. در این درخواست، فیلد `title` الزامی است؛ اما ارسال فایل جایگزین اختیاری است.

`PATCH /api/documents/{id}/`

درخواست PATCH برای به‌روزرسانی بخشی از اطلاعات سند استفاده می‌شود. تنها فیلدهایی که در درخواست ارسال شده‌اند تغییر می‌کنند.

در صورت ارسال فایل جایگزین، سند مجدداً پردازش می‌شود. اگر پردازش فایل جدید با شکست مواجه شود، API پاسخ `422 Unprocessable Entity` برمی‌گرداند و وضعیت قبلی سند را بازیابی می‌کند.

### پرسش و پاسخ

نقطه پایانی پرسش و پاسخ از فرایند RAG برای بازیابی بخش‌های مرتبط اسناد و تولید پاسخ استفاده می‌کند.

| متد | نقطه پایانی | توضیحات |
|---|---|---|
| POST | `/api/qa/ask/` | ارسال پرسش و دریافت پاسخ |

**بدنه درخواست**

`POST /api/qa/ask/`

نوع محتوا: `application/json`

| فیلد | نوع | الزامی | توضیحات |
|---|---|---|---|
| `question` | String | بله | پرسش کاربر |
| `document_id` | Integer | خیر | محدود کردن جست‌وجو به یک سند مشخص |

اگر `document_id` ارسال نشود، بازیابی اطلاعات می‌تواند از میان اسناد موجود انجام شود.

پاسخ این API شامل پاسخ تولیدشده، منابع بازیابی‌شده، وضعیت پاسخ و اطلاعات مربوط به استفاده یا عدم استفاده از مدل زبانی است.

### تاریخچه پرسش‌ها

نقاط پایانی تاریخچه امکان مشاهده پرسش‌های قبلی و پاسخ‌های آن‌ها را فراهم می‌کنند.

| متد | نقطه پایانی | توضیحات |
|---|---|---|
| GET | `/api/qa/history/` | دریافت تاریخچه پرسش‌ها |
| GET | `/api/qa/history/{id}/` | دریافت جزئیات یک رکورد مشخص |

فهرست تاریخچه از صفحه‌بندی مبتنی بر شماره صفحه استفاده می‌کند. اندازه پیش‌فرض هر صفحه ۲۰ رکورد است. با پارامتر `page_size` می‌توان تعداد رکوردهای هر صفحه را تغییر داد؛ حداکثر این مقدار ۱۰۰ است.

نمونه:

```text
GET /api/qa/history/?page=2&page_size=10
```

پاسخ فهرست تاریخچه شامل اطلاعات خلاصه هر رکورد است. نقطه پایانی جزئیات، علاوه بر این اطلاعات، منابع بازیابی‌شده را نیز برمی‌گرداند.

<a id="api-fa-examples"></a>
## 🧾 نمونه درخواست‌ها و پاسخ‌ها

### بارگذاری سند

نمونه فیلدهای درخواست:

```text
title: Library Guide
file: library_guide.docx
```

نمونه پاسخ:

```json
{
  "id": 1,
  "title": "Library Guide",
  "file_name": "library_guide.docx",
  "status": "completed",
  "chunk_count": 3,
  "created_at": "2026-11-18T10:30:00Z",
  "updated_at": "2026-11-18T10:30:00Z"
}
```

### ارسال پرسش

نمونه درخواست:

```json
{
  "question": "How many books can an undergraduate student borrow?",
  "document_id": 1
}
```

نمونه پاسخ:

```json
{
  "id": 12,
  "question": "How many books can an undergraduate student borrow?",
  "answer": "An undergraduate student can borrow ...",
  "status": "answered",
  "sources": [
    {
      "source_id": "S1",
      "document_id": 1,
      "document_title": "Library Guide",
      "chunk_index": 0,
      "similarity": 0.91,
      "distance": 0.09,
      "content": "..."
    }
  ],
  "used_llm": true,
  "created_at": "2026-11-18T10:30:00Z"
}
```

مقادیر بالا صرفاً نمونه هستند. پاسخ و محتوای منابع واقعی به اسناد بارگذاری‌شده و پرسش کاربر بستگی دارند.

**توضیح فیلدهای پاسخ**

| فیلد | توضیحات |
|---|---|
| `id` | شناسه رکورد پرسش و پاسخ |
| `question` | پرسش ارسال‌شده |
| `answer` | پاسخ تولیدشده یا پیام از پیش تعریف‌شده در صورت نبود پاسخ |
| `status` | وضعیت پاسخ؛ `answered` یا `no_answer` |
| `sources` | بخش‌های بازیابی‌شده از اسناد که به‌عنوان منبع استفاده شده‌اند |
| `used_llm` | مشخص می‌کند که آیا مدل زبانی فراخوانی شده است یا خیر |
| `created_at` | زمان ایجاد رکورد |

هر شیء در آرایه `sources` شامل فیلدهای زیر است:

| فیلد | توضیحات |
|---|---|
| `source_id` | شناسه منبع مانند `S1` |
| `document_id` | شناسه سند منبع |
| `document_title` | عنوان سند منبع |
| `chunk_index` | شماره بخش بازیابی‌شده |
| `similarity` | امتیاز شباهت |
| `distance` | فاصله کسینوسی |
| `content` | محتوای بخش بازیابی‌شده |

### تاریخچه پرسش‌ها

نمونه پاسخ صفحه‌بندی‌شده:

```json
{
  "count": 25,
  "next": "http://localhost:8000/api/qa/history/?page=2",
  "previous": null,
  "results": [
    {
      "id": 12,
      "question": "How many books can an undergraduate student borrow?",
      "answer": "An undergraduate student can borrow ...",
      "status": "answered",
      "created_at": "2026-11-18T10:30:00Z"
    }
  ]
}
```

نقطه پایانی جزئیات تاریخچه، علاوه بر فیلدهای موجود در پاسخ فهرست، فیلد `sources` را نیز شامل می‌شود.

<a id="api-fa-validation"></a>
## ✅ قوانین اعتبارسنجی

### بارگذاری و به‌روزرسانی اسناد

- فقط فایل‌هایی با پسوند `.docx` پذیرفته می‌شوند.
- حداکثر حجم مجاز فایل ۱۰ مگابایت است.
- فایل‌های خالی پذیرفته نمی‌شوند.
- عنوان سند الزامی است و نمی‌تواند فقط شامل فاصله باشد.
- فایل جایگزین پیش از موفقیت‌آمیز تلقی شدن عملیات به‌روزرسانی، مجدداً پردازش می‌شود.

### ارسال پرسش

- فیلد `question` الزامی است.
- فاصله‌های ابتدا و انتهای پرسش حذف می‌شوند.
- حداکثر طول پرسش ۵۰۰۰ کاراکتر است.
- در صورت ارسال `document_id`، این شناسه باید متعلق به یک سند موجود باشد.

<a id="api-fa-status-codes"></a>
## ⚠️ کدهای وضعیت HTTP

| کد وضعیت | مفهوم | کاربرد رایج |
|---|---|---|
| `200 OK` | درخواست موفق | دریافت یا به‌روزرسانی یک منبع |
| `201 Created` | ایجاد منبع جدید | بارگذاری موفق سند |
| `204 No Content` | درخواست موفق بدون بدنه پاسخ | حذف موفق سند |
| `400 Bad Request` | درخواست نامعتبر | خطاهای اعتبارسنجی یا ورودی نامعتبر برای پرسش |
| `404 Not Found` | منبع پیدا نشد | سند یا رکورد تاریخچه موردنظر وجود ندارد |
| `422 Unprocessable Entity` | شکست در پردازش | پردازش فایل جایگزین ناموفق بوده و وضعیت قبلی سند بازیابی شده است |
| `503 Service Unavailable` | سرویس در دسترس نیست | خطا در تنظیمات یا تولید پاسخ توسط مدل زبانی |

کد وضعیت دقیق به نوع درخواست و خطای رخ‌داده بستگی دارد.

## 📚 مستندات تعاملی API

پروژه سه رابط برای مشاهده مستندات API ارائه می‌دهد:

| رابط | آدرس | کاربرد |
|---|---|---|
| Swagger UI | `/api/docs/` | آزمایش تعاملی API |
| ReDoc | `/api/redoc/` | مشاهده ساختاریافته مستندات |

- Swagger: `http://localhost:8000/api/docs/`
- ReDoc: `http://localhost:8000/api/redoc/`
- OpenAPI Schema: `http://localhost:8000/api/schema/`

<a id="api-fa-authentication"></a>
## 🔐 احراز هویت

در نسخه فعلی پروژه، احراز هویت API و سیستم مجوزدهی کاربران پیاده‌سازی نشده است. بنابراین نقاط پایانی API در تنظیمات فعلی توسعه، بدون احراز هویت در دسترس هستند.

این رفتار متناسب با محدوده فعلی پروژه است و نباید به‌عنوان پیکربندی امنیتی مناسب برای محیط عملیاتی در نظر گرفته شود.
