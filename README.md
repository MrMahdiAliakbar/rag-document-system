# RAG Document System

A document-based question-answering system built with Django REST Framework and Retrieval-Augmented Generation (RAG).

The system allows users to upload DOCX documents, retrieve relevant information through semantic search, and ask questions based on uploaded content. Answers are generated by a Large Language Model (LLM) using retrieved document passages as context, with relevant sources returned alongside each answer.

## ✨ Key Features

- DOCX document upload and validation.
- Document retrieval, update, and deletion.
- Text extraction from document paragraphs and tables.
- Token-based text chunking with overlap.
- Multilingual vector embeddings using FastEmbed.
- Semantic search using PostgreSQL and pgvector.
- RAG-based question answering through OpenRouter.
- Source references returned with generated answers.
- Question history with pagination.
- Django Admin for document and question-history management.
- Interactive API documentation using Swagger UI and ReDoc.

<a name="readme-en-system-architecture"></a>
## 🏗️ System Architecture

The application follows a modular Django architecture.

### Main Components

- **Django REST Framework:** Exposes document management and question-answering functionality through REST API endpoints.
- **Documents App:** Handles document validation, text extraction, chunking, embedding generation, document storage, and semantic retrieval.
- **QA App:** Handles question submission, context retrieval, LLM communication, answer generation, and question history.
- **PostgreSQL:** Stores application data and document content.
- **pgvector:** Stores and searches vector embeddings.
- **FastEmbed:** Generates multilingual embeddings.
- **LangChain:** Connects the retrieved context to the language model.
- **OpenRouter:** Provides access to the configured LLM.
- **Django Admin:** Provides an administrative interface for managing stored records.

<a name="readme-en-rag-pipeline"></a>
## 🔄 RAG Pipeline

### Document Indexing

1. A user uploads a DOCX document.
2. The system validates its extension and file size.
3. Text is extracted from paragraphs and tables.
4. The extracted text is divided into chunks of up to 450 tokens, with a 60-token overlap.
5. FastEmbed generates 384-dimensional multilingual embeddings using the `passage:` prefix.
6. Document chunks and their embeddings are stored in PostgreSQL using pgvector.
7. The document status is updated to `completed` or `failed`.

### Question Answering

1. A user submits a question through the REST API.
2. The question is converted into an embedding using the `query:` prefix.
3. pgvector retrieves the most similar chunks from completed documents.
4. Results are filtered using the configured cosine-distance threshold.
5. Relevant passages are assembled into a context.
6. LangChain sends the question and context to the configured OpenRouter model.
7. The model generates an answer using the retrieved context.
8. The answer and its source references are stored in question history and returned to the user.

### Handling Insufficient Information

The system handles insufficient information in two ways:

- **No relevant chunks retrieved:** If no chunks meet the configured relevance threshold, the system returns a predefined no-answer message without calling the LLM. In this case, `used_llm` is `false`.
- **Retrieved context is insufficient:** If relevant chunks are retrieved but the LLM determines that the provided context is insufficient to answer the question, the system returns the predefined no-answer message after calling the LLM. In this case, `used_llm` is `true`.

<a name="readme-en-getting-started"></a>
## 🚀 Getting Started

### 1. Clone the Repository

```bash
git clone https://github.com/MrMahdiAliakbar/rag-document-system.git
cd rag-document-system
```

### 2. Configure Environment Variables

Create a `.env` file in the project root by copying the example file:

```powershell
Copy-Item .env.example .env
```

Configure the values in `.env`:

```env
DJANGO_SECRET_KEY=replace-with-a-secure-secret-key
DJANGO_DEBUG=True
DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1,0.0.0.0

DB_NAME=rag_db
DB_USER=rag_user
DB_PASSWORD=change-this-database-password
DB_HOST=db
DB_PORT=5432

OPENROUTER_API_KEY=your-openrouter-api-key
OPENROUTER_MODEL=qwen/qwen3-32b:free
```

The following RAG settings are optional and use the defaults shown below when not provided:

```env
RAG_TOP_K=5
RAG_MAX_COSINE_DISTANCE=0.20
RAG_LLM_MAX_TOKENS=1024
RAG_LLM_TIMEOUT=60000
```

Replace all placeholder values with your own configuration.

Keep the `.env` file private. Never commit API keys, passwords, or other secrets to version control.

### 3. Build and Run the Containers

```bash
docker compose up --build -d
```

Check container status:

```bash
docker compose ps
```

View application logs:

```bash
docker compose logs -f web
```

### 4. Apply Database Migrations

```bash
docker compose exec web python manage.py migrate
```

### 5. Create an Administrator Account

```bash
docker compose exec web python manage.py createsuperuser
```

Follow the prompts to configure the administrator account.

### 6. Open the Available Interfaces

After the containers are running, use the following local addresses:

| Interface | Address | Purpose |
|---|---|---|
| Django Admin | [http://localhost:8000/admin/](http://localhost:8000/admin/) | Manage documents and question history |
| Swagger UI | [http://localhost:8000/api/docs/](http://localhost:8000/api/docs/) | Explore API endpoints and send test requests |
| ReDoc | [http://localhost:8000/api/redoc/](http://localhost:8000/api/redoc/) | Read the API reference in a structured format |
| OpenAPI Schema | [http://localhost:8000/api/schema/](http://localhost:8000/api/schema/) | Access the generated OpenAPI schema |

These addresses are available only while the application is running locally.

## 🔌 API Endpoints

### Document Management

Base path: `/api/documents/`

| Method | Endpoint | Description |
|---|---|---|
| GET | `/api/documents/` | List documents |
| POST | `/api/documents/` | Upload and process a DOCX document |
| GET | `/api/documents/{id}/` | Retrieve document details |
| PUT | `/api/documents/{id}/` | Update document information |
| PATCH | `/api/documents/{id}/` | Partially update document information |
| DELETE | `/api/documents/{id}/` | Delete a document and its stored file |

Document upload and update requests use `multipart/form-data`.

### Question Answering

Base path: `/api/qa/`

| Method | Endpoint | Description |
|---|---|---|
| POST | `/api/qa/ask/` | Submit a question and receive an answer |
| GET | `/api/qa/history/` | Retrieve paginated question history |
| GET | `/api/qa/history/{id}/` | Retrieve a history entry with its sources |

Question requests use JSON.

The `document_id` field is optional. When provided, retrieval is restricted to the specified document.

Question history is ordered from newest to oldest. The list endpoint supports `page` and `page_size` query parameters.

The question status returned by the API is derived from the answer content. It is not stored as a separate database field.

For detailed request and response information, see the [API Documentation](docs/API.md).

<a name="readme-en-limitations"></a>
## 🔐 Limitations and Security Notes

- Only DOCX documents are supported by the current upload workflow.
- The maximum accepted document size is 10 MB.
- The current API endpoints allow unauthenticated access.
- The Docker configuration is intended for development and testing, not production deployment.
- Django's development server is used in the current Docker setup.
- The database port is published only on the host loopback interface (`127.0.0.1:5432`), rather than on all network interfaces.
- A valid `DJANGO_SECRET_KEY` and the required database environment variables must be provided before the application starts.
- The default value of `DJANGO_DEBUG` in Django settings is `False`. The provided `.env.example` enables it for local development.
- Answer quality depends on document content, retrieval relevance, and the configured language model.
- Generating answers requires a valid OpenRouter API key and access to the selected model.
