
# سامانه پرسش و پاسخ مبتنی بر اسناد (RAG)

[English](README.md) | Persian

یک سامانه پرسش و پاسخ مبتنی بر اسناد که با استفاده از Django REST Framework و معماری تولید افزوده با بازیابی (Retrieval-Augmented Generation یا RAG) توسعه داده شده است.

این سامانه امکان بارگذاری اسناد DOCX، بازیابی اطلاعات مرتبط از طریق جستجوی معنایی و طرح پرسش بر اساس محتوای اسناد بارگذاری‌شده را فراهم می‌کند. پاسخ‌ها با استفاده از یک مدل زبانی بزرگ (LLM) و بر اساس محتوای بازیابی‌شده تولید می‌شوند و منابع مرتبط نیز در کنار پاسخ ارائه می‌شوند.

## معرفی پروژه

سامانه RAG Document System یک برنامه سمت سرور است که با هدف فراهم کردن قابلیت پرسش و پاسخ بر اساس اسناد بارگذاری‌شده طراحی شده است.

این سامانه به‌جای اتکا به دانش عمومی مدل زبانی، ابتدا بخش‌های مرتبط را از میان اسناد بارگذاری‌شده بازیابی می‌کند و سپس از آن‌ها به‌عنوان زمینه برای تولید پاسخ استفاده می‌کند.

برنامه از طریق یک RESTful API امکاناتی مانند مدیریت اسناد، جستجوی معنایی، پرسش و پاسخ مبتنی بر RAG، ارائه منابع پاسخ و نگهداری تاریخچه پرسش‌ها را فراهم می‌کند. همچنین یک پنل مدیریتی مبتنی بر Django Admin برای مدیریت اطلاعات برنامه در نظر گرفته شده است.

## قابلیت‌های اصلی

- **بارگذاری اسناد:** بارگذاری فایل‌های DOCX برای پردازش و نمایه‌سازی.
- **مدیریت اسناد:** مشاهده، ویرایش و حذف اسناد بارگذاری‌شده.
- **استخراج متن:** استخراج متن از پاراگراف‌ها و جدول‌های اسناد.
- **تقسیم متن به بخش‌ها:** تقسیم محتوای استخراج‌شده به بخش‌های کوچک‌تر با هم‌پوشانی.
- **تولید بردارهای تعبیه‌شده:** تولید بردارهای معنایی چندزبانه برای بخش‌های اسناد.
- **جستجوی معنایی:** بازیابی بخش‌های مرتبط اسناد با استفاده از شباهت برداری.
- **پرسش و پاسخ مبتنی بر RAG:** تولید پاسخ با استفاده از محتوای بازیابی‌شده اسناد.
- **ارائه منابع پاسخ:** بازگرداندن بخش‌های مرتبط اسناد در کنار پاسخ تولیدشده.
- **تاریخچه پرسش‌ها:** ذخیره پرسش‌ها، پاسخ‌ها، وضعیت‌ها و منابع بازیابی‌شده.
- **REST API:** ارائه قابلیت‌های برنامه از طریق مسیرهای API مستندشده.
- **Django Admin:** مدیریت اسناد و اطلاعات برنامه از طریق پنل مدیریت.
- **پشتیبانی از Docker:** اجرای برنامه و پایگاه داده PostgreSQL با استفاده از Docker Compose.

## معماری سیستم

این برنامه از یک معماری ماژولار مبتنی بر Django استفاده می‌کند که در آن مسئولیت مدیریت اسناد و پردازش پرسش‌ها در بخش‌های جداگانه قرار گرفته است.

### اجزای اصلی

- **Django REST Framework:** ارائه قابلیت‌های برنامه از طریق مسیرهای REST API.
- **برنامه Documents:** مدیریت بارگذاری و اعتبارسنجی اسناد، استخراج متن، تقسیم‌بندی، تولید embedding و مدیریت اسناد.
- **برنامه QA:** مدیریت ارسال پرسش، بازیابی معنایی، ارتباط با مدل زبانی، تولید پاسخ و تاریخچه پرسش‌ها.
- **PostgreSQL + pgvector:** ذخیره اطلاعات برنامه و بردارهای تعبیه‌شده.
- **FastEmbed:** تولید embedding برای بخش‌های اسناد و پرسش‌های کاربران.
- **LangChain:** یکپارچه‌سازی فرایند تولید افزوده با بازیابی با مدل زبانی.
- **OpenRouter:** فراهم کردن دسترسی به مدل زبانی پیکربندی‌شده.
- **Django Admin:** ارائه پنل مدیریتی برای مدیریت اطلاعات برنامه.

## مراحل پردازش RAG

فرایند پرسش و پاسخ در سامانه شامل مراحل زیر است:

۱. کاربر یک سند DOCX بارگذاری می‌کند.

۲. سامانه فایل بارگذاری‌شده را اعتبارسنجی می‌کند.

۳. متن موجود در پاراگراف‌ها و جدول‌های سند استخراج می‌شود.

۴. متن استخراج‌شده به بخش‌های کوچک‌تر و دارای هم‌پوشانی تقسیم می‌شود.

۵. کتابخانه FastEmbed برای بخش‌های متن، بردارهای معنایی تولید می‌کند.

۶. بخش‌های متن و بردارهای مربوط به آن‌ها در PostgreSQL با استفاده از pgvector ذخیره می‌شوند.

۷. کاربر پرسش خود را از طریق REST API ارسال می‌کند.

۸. پرسش کاربر به یک بردار تعبیه‌شده تبدیل می‌شود.

۹. جستجوی معنایی، مرتبط‌ترین بخش‌های اسناد را بازیابی می‌کند.

۱۰. محتوای بازیابی‌شده به‌عنوان زمینه در اختیار مدل زبانی قرار می‌گیرد.

۱۱. مدل زبانی بر اساس محتوای بازیابی‌شده پاسخ تولید می‌کند.

۱۲. پاسخ، وضعیت آن و منابع مرتبط در تاریخچه پرسش‌ها ذخیره شده و به کاربر بازگردانده می‌شوند.

اگر هیچ منبع به‌اندازه کافی مرتبطی پیدا نشود، سامانه بر اساس محتوای نامرتبط پاسخی تولید نمی‌کند.

## پیش‌نیازها

برای اجرای پروژه به موارد زیر نیاز دارید:

- Docker
- Docker Compose
- کلید API سرویس OpenRouter

برنامه با استفاده از Docker Compose، برنامه Django و پایگاه داده PostgreSQL را اجرا می‌کند.

## شروع به کار

### ۱. دریافت مخزن پروژه

```bash
git clone https://github.com/YOUR_USERNAME/rag-document-system.git
cd rag-document-system
```

### ۲. تنظیم متغیرهای محیطی

یک فایل با نام `.env` در مسیر اصلی پروژه ایجاد کنید.

متغیرهای محیطی موردنیاز را در آن تنظیم کنید:

```env
DJANGO_SECRET_KEY=replace-with-a-secure-secret-key
DJANGO_DEBUG=True
DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1,0.0.0.0

DB_NAME=rag_db
DB_USER=rag_user
DB_PASSWORD=change-this-database-password
DB_HOST=db
DB_PORT=5432

OPENROUTER_API_KEY=your-openrouter-api-key
OPENROUTER_MODEL=qwen/qwen3-32b:free

RAG_TOP_K=5
RAG_MAX_COSINE_DISTANCE=0.20
RAG_LLM_MAX_TOKENS=1024
RAG_LLM_TIMEOUT=60000
```

مقادیر نمونه را با تنظیمات موردنظر خود جایگزین کنید.

فایل `.env` حاوی اطلاعات محرمانه است؛ آن را خصوصی نگه دارید و در مخزن Git قرار ندهید.

### ۳. اجرای پروژه با Docker Compose

برای ساخت Image برنامه و اجرای کانتینرها، دستور زیر را اجرا کنید:

```bash
docker compose up --build -d
```

وضعیت کانتینرهای در حال اجرا را بررسی کنید:

```bash
docker compose ps
```

برای مشاهده گزارش اجرای برنامه:

```bash
docker compose logs -f web
```

پس از اجرا، مسیرهای زیر در دسترس خواهند بود:

- برنامه: http://localhost:8000/
- پنل مدیریت Django: http://localhost:8000/admin/
- رابط Swagger: http://localhost:8000/api/docs/
- مستندات ReDoc: http://localhost:8000/api/redoc/

### ۴. اجرای Migrationها

برای اعمال Migrationهای پایگاه داده، دستور زیر را اجرا کنید:

```bash
docker compose exec web python manage.py migrate
```

### ۵. ساخت حساب مدیر

برای دسترسی به پنل مدیریت Django، یک حساب مدیر ایجاد کنید:

```bash
docker compose exec web python manage.py createsuperuser
```

سپس طبق راهنما، نام کاربری، ایمیل و رمز عبور حساب مدیر را تعیین کنید.

## مستندات API

مستندات API با استفاده از **drf-spectacular** تولید می‌شوند و امکان مشاهده و بررسی تعاملی مسیرهای موجود را فراهم می‌کنند.

پس از اجرای برنامه، از مسیرهای زیر استفاده کنید:

| نوع مستندات | آدرس |
|---|---|
| Swagger UI | http://localhost:8000/api/docs/ |
| ReDoc | http://localhost:8000/api/redoc/ |
| OpenAPI Schema | http://localhost:8000/api/schema/ |

با استفاده از Swagger UI می‌توانید مسیرهای API را بررسی کنید، ساختار درخواست‌ها و پاسخ‌ها را ببینید و درخواست‌های آزمایشی ارسال کنید.

## مسیرهای API

### مدیریت اسناد

مسیر پایه: `/api/documents/`

| متد | مسیر | توضیحات |
|---|---|---|
| GET | `/api/documents/` | دریافت فهرست اسناد بارگذاری‌شده |
| POST | `/api/documents/` | بارگذاری سند جدید |
| GET | `/api/documents/{id}/` | دریافت اطلاعات یک سند |
| PUT | `/api/documents/{id}/` | ویرایش کامل یک سند |
| PATCH | `/api/documents/{id}/` | ویرایش بخشی از اطلاعات سند |
| DELETE | `/api/documents/{id}/` | حذف سند |

### پرسش و پاسخ

مسیر پایه: `/api/qa/`

| متد | مسیر | توضیحات |
|---|---|---|
| POST | `/api/qa/ask/` | ارسال پرسش و دریافت پاسخ |
| GET | `/api/qa/history/` | دریافت تاریخچه صفحه‌بندی‌شده پرسش‌ها |
| GET | `/api/qa/history/{id}/` | دریافت جزئیات یک رکورد تاریخچه به همراه منابع |

تاریخچه پرسش‌ها از جدیدترین به قدیمی‌ترین مرتب می‌شود. مسیر فهرست، اطلاعات را به‌صورت صفحه‌بندی‌شده برمی‌گرداند؛ درحالی‌که مسیر جزئیات، منابع مرتبط با آن پرسش را نیز شامل می‌شود.

## اجرای تست‌ها

این پروژه شامل تست‌های خودکار برای مدیریت اسناد، پرسش و پاسخ و قابلیت‌های API است.

برای اجرای مجموعه تست‌ها در کانتینر برنامه، دستور زیر را اجرا کنید:

```bash
docker compose exec web python manage.py test
```

در مرحله تست و اعتبارسنجی پروژه، **۵۸ تست خودکار** با موفقیت اجرا شدند.

| `RAG_LLM_TIMEOUT` | مهلت زمانی درخواست به مدل زبانی بر حسب میلی‌ثانیه | `60000` |

## محدودیت‌های فعلی

- فرایند فعلی بارگذاری اسناد از فایل‌های DOCX پشتیبانی می‌کند.
- کیفیت پاسخ‌ها به محتوای اسناد، میزان ارتباط نتایج بازیابی‌شده و مدل زبانی پیکربندی‌شده وابسته است.
- تولید پاسخ به کلید API معتبر OpenRouter و دسترسی به مدل انتخاب‌شده نیاز دارد.
- پیکربندی Docker ارائه‌شده برای توسعه و تست در نظر گرفته شده است و برای استقرار Production طراحی نشده است.
